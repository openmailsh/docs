Add one URL to your client and your agent gets tools to create an inbox, read threads, and reply. Sign in with OAuth or an API key. No CLI or SDK install.

<Info>Without a credential, `/mcp` answers `401` so your client starts the sign-in flow. For an agent that only needs to read these docs, use `https://mcp.openmail.sh/mcp/public`: no sign-in, just `search_docs` and `get_docs`.</Info>

## First run

Ask your agent: *"Set up an inbox for this agent and show me the address."*

It calls `setup_agent_email`, which returns a plan first. Confirm, and it creates the inbox. What happens to the key depends on how you signed in: over OAuth the session already has access, so no key is minted and the tool points you to the console if a separate agent needs one. Over an API key, the new inbox-scoped key appears once in the tool result.

<Warning>Move that key to the agent's environment straight away, and revoke it from the console if the transcript is shared.</Warning>

## Tools

<Note>19 tools. Your client reads the live list from the server, so this table can lag behind by a release.</Note>

| Tool | What it does |
| --- | --- |
| `search_docs`, `get_docs` | Search and read these docs. Also available without sign-in at `/mcp/public`. |
| `auth_me` | Which organisation and inbox this credential can see. |
| `setup_agent_email` | Plan, then create an inbox and mint a scoped key. |
| `list_inboxes`, `get_inbox`, `create_inbox`, `mint_inbox_key` | Inbox management. |
| `list_unread_threads` | Unread threads whose latest message is `autoReplyable`: sent by a person or another agent. Spam, marketing, bounces, and machine-generated mail (no-reply, OTPs, receipts) are filtered out. |
| `read_thread` | Full thread as Markdown with timestamps, `autoReplyable` flags, and attachment message ids. Quoted reply history is stripped. |
| `reply_to_thread`, `send_email` | Reply in-thread, or start a new one. `send_email` names the inbox it used when you did not pass `inbox_id`. |
| `mark_thread_read` | Mark a thread handled. |
| `get_attachment_text` | Extracted text from an attachment. Use the `message:` id shown in `read_thread`. |
| `list_domains`, `add_domain`, `get_domain`, `verify_domain` | Custom domains with pasteable DNS records. Pro plan. |
| `send_mcp_feedback` | Report a confusing or broken tool to the OpenMail team. |

Tools follow the credential. An inbox-scoped key hides `list_inboxes`, `setup_agent_email`, and the domain tools.

## Narrow what the agent can do

| Goal | URL |
| --- | --- |
| Read only, no sending | `https://mcp.openmail.sh/mcp/readonly` or `?readonly=true` |
| One inbox, no discovery | `https://mcp.openmail.sh/mcp/inbox/INBOX_ID` |
| Fewer tools | `?toolsets=mailbox,docs` or the `X-MCP-Toolsets` header |

## What the connected client can do

A connected client receives whatever the tools return: thread contents, attachment text, inbox addresses. With the **Send** scope it can also send and reply as your inbox. The client handles that data under its own terms, so connect only clients you trust and leave scopes unticked when the agent does not need them. Revoking the connection in [MCP settings](https://console.openmail.sh/settings/mcp), or the API key it uses, stops access at once.

## Usage analytics

The server records how tools are used so the OpenMail team can fix the ones that fail or confuse agents. Each tool also accepts an optional `context` argument where the agent says in one line what it is trying to do; that line is recorded too.

| Recorded | Never recorded |
| --- | --- |
| Tool name, success or failure, latency | Message bodies, subjects, recipients |
| Client name and version (Claude, Cursor, ChatGPT) | Attachment text |
| The agent's `context` line | Inbox names and display names |
| Your organisation id | API keys and OAuth tokens |

Tool results are dropped before they leave the server, except for `search_docs` and `get_docs`, which return public documentation.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The consent page asks for an account you do not have">
    Sign up at [console.openmail.sh](https://console.openmail.sh/signup) first, then start the connection again from your client.
  </Accordion>
  <Accordion title="You picked the wrong organisation">
    Revoke the connection in [MCP settings](https://console.openmail.sh/settings/mcp), then connect again from the client. The consent page shows the organisation picker each time.
  </Accordion>
  <Accordion title="401 with an API key">
    Check the key starts with `om_`, was copied in full, and has not been revoked in the console. The key goes in the `Authorization: Bearer` header, not the URL. In Cursor, a leftover `om_YOUR_KEY` placeholder gives the same error.
  </Accordion>
  <Accordion title="Tools are missing">
    An inbox-scoped key hides `list_inboxes`, `setup_agent_email`, and the domain tools by design. If you changed scopes on the consent page, disconnect and reconnect so the client reloads the tool list.
  </Accordion>
  <Accordion title="Claude says it cannot reach OpenMail">
    Open **Settings → Connectors** and check that OpenMail shows as connected. If not, repeat the Claude steps above.
  </Accordion>
</AccordionGroup>
