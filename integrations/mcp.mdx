<Info>Without a credential, `/mcp` answers `401` and your client starts sign-in. An agent that only needs these docs can use `https://mcp.openmail.sh/mcp/public`: no sign-in, just `search_docs` and `get_docs`.</Info>

## First run

Ask your agent: *"Set up an inbox for this agent and show me the address."*

It calls `setup_agent_email`, which shows a plan first. Confirm, and it creates the inbox. Over OAuth no key is minted; the session already has access, and the tool points to the console if another agent needs one. Over an API key, a new inbox-scoped key appears once in the result.

<Warning>Move that key to the agent's environment now. If the transcript is shared, revoke it in the console.</Warning>

## Tools

<Note>19 tools. Your client reads the live list from the server; this table can lag a release.</Note>

| Tool | What it does |
| --- | --- |
| `search_docs`, `get_docs` | Search and read these docs. Also available without sign-in at `/mcp/public`. |
| `auth_me` | Which organisation and inbox this credential can see. |
| `setup_agent_email` | Plan, then create an inbox and mint a scoped key. |
| `list_inboxes`, `get_inbox`, `create_inbox`, `mint_inbox_key` | Inbox management. |
| `list_unread_threads` | Unread threads whose latest message is `autoReplyable`: sent by a person or another agent. Spam, marketing, bounces, and machine-generated mail (no-reply, OTPs, receipts) are filtered out. |
| `read_thread` | Full thread as Markdown with timestamps, `autoReplyable` flags, and attachment message ids. Quoted reply history is stripped. |
| `reply_to_thread`, `send_email` | Reply in-thread, or start a new one. `send_email` names the inbox it used when you did not pass `inbox_id`. |
| `mark_thread_read` | Mark a thread handled. |
| `get_attachment_text` | Extracted text from an attachment. Use the `message:` id shown in `read_thread`. |
| `list_domains`, `add_domain`, `get_domain`, `verify_domain` | Custom domains with pasteable DNS records. Pro plan. |
| `send_mcp_feedback` | Report a confusing or broken tool to the OpenMail team. |

Tools follow the credential. An inbox-scoped key hides `list_inboxes`, `setup_agent_email`, and the domain tools.

## Narrow what the agent can do

| Goal | URL |
| --- | --- |
| Read only, no sending | `https://mcp.openmail.sh/mcp/readonly` or `?readonly=true` |
| One inbox, no discovery | `https://mcp.openmail.sh/mcp/inbox/INBOX_ID` |
| Fewer tools | `?toolsets=mailbox,docs` or the `X-MCP-Toolsets` header |

## What the connected client can do

A connected client sees whatever the tools return: thread contents, attachment text, inbox addresses. With **Send** it can also send and reply as your inbox. That data falls under the client's own terms, so connect only clients you trust and untick scopes the agent does not need. Revoking the connection in [MCP settings](https://console.openmail.sh/settings/mcp), or its API key, stops access at once.

## Usage analytics

The server records how tools are used so the OpenMail team can fix the ones that fail or confuse agents. Each tool accepts an optional `context` argument: one line from the agent on what it is trying to do. That line is recorded too.

| Recorded | Never recorded |
| --- | --- |
| Tool name, success or failure, latency | Message bodies, subjects, recipients |
| Client name and version (Claude, Cursor, ChatGPT) | Attachment text |
| The agent's `context` line | Inbox names and display names |
| Your organisation id | API keys and OAuth tokens |

Tool results never leave the server, except from `search_docs` and `get_docs`, which return public documentation.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The consent page asks for an account you do not have">
    Sign up at [console.openmail.sh](https://console.openmail.sh/signup), then connect again from your client.
  </Accordion>
  <Accordion title="You picked the wrong organisation">
    Revoke it in [MCP settings](https://console.openmail.sh/settings/mcp) and connect again. The consent page shows the picker each time.
  </Accordion>
  <Accordion title="401 with an API key">
    Check the key starts with `om_`, is complete, and is not revoked. It belongs in the `Authorization: Bearer` header, not the URL. A leftover `om_YOUR_KEY` placeholder in Cursor gives the same error.
  </Accordion>
  <Accordion title="Tools are missing">
    An inbox-scoped key hides `list_inboxes`, `setup_agent_email`, and the domain tools on purpose. After changing scopes, disconnect and reconnect so the client reloads the list.
  </Accordion>
  <Accordion title="Claude says it cannot reach OpenMail">
    Check **Settings → Connectors** shows OpenMail as connected. If not, repeat the Claude steps.
  </Accordion>
</AccordionGroup>
