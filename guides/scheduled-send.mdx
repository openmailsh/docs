Pass `sendAt` when you [send an email](/api-reference/messages/send-email) to hold it until that time. The response is `202` with `status: scheduled`. Leave `sendAt` out and the email goes immediately.

Rate limits, recipient policy, and content checks run when the email goes out, not when you schedule it.

## How it works

`sendAt` is an ISO-8601 time, at least 30 seconds ahead and within 30 days.

<CodeGroup>

```bash curl
curl -X POST "https://api.openmail.sh/v1/inboxes/$OPENMAIL_INBOX_ID/send" \
  -H "Authorization: Bearer $OPENMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "to": "recipient@example.com",
    "subject": "Thursday",
    "body": "Thursday works.",
    "sendAt": "2026-11-24T06:00:00.000Z"
  }'
```

```bash CLI
openmail send --to recipient@example.com --subject "Thursday" \
  --body "Thursday works." --send-at 2026-11-24T06:00:00Z
```

</CodeGroup>

The same `Idempotency-Key` returns this scheduled email until it goes out, then the sent message. A repeat of a cancelled or failed send returns `scheduled_send_closed`. Use a new key to schedule it again.

Sending a [draft](/api-reference/drafts/send-email-draft) takes the same field. The draft leaves Drafts and becomes a scheduled send.

## Change or cancel

`GET /v1/inboxes/{id}/scheduled-sends` lists what is still waiting. The default is `status=scheduled`, up to 50, soonest first. Pass a comma-separated `status` to include `failed`, `cancelled`, `sending`, or `sent`.

`PATCH /v1/inboxes/{id}/scheduled-sends/{sendId}` moves the time. You can change `sendAt` only.

```json
{ "sendAt": "2026-11-25T06:00:00.000Z" }
```

`DELETE /v1/inboxes/{id}/scheduled-sends/{sendId}` stops a send that has not gone out. A send that is already going out or has been sent cannot be cancelled.

From the [CLI](/integrations/cli#scheduled), `openmail scheduled list`, `reschedule`, and `cancel` call the same three endpoints.
